## Architecture and semantics

[Architecture document](v0.3-chunked-conjunction-screening.md) contains the complete
contract. One global grid is sliced into 900-second chunks with one shared sample.
The boundary state list is reused, including quality/failure decisions. Numerical
SGP4 searches keep candidate time +/- one step, clamped to the global window.
Candidate structures are released before the next chunk; only final events and
small counters are aggregated. `screening` in the service result is a counters-only
summary with empty candidate/conjunction tuples.

Event merging now normalizes the pair and connects neighboring TCAs only when
SGP4 threshold continuity is established across their intervening interval.
An observed exit preserves separate episodes, including below one second apart.
Smaller miss distance wins, followed by earlier TCA; results are returned in TCA
order. Exact selected orbital element IDs persist without a second canonical
query. `unique_candidates` means total chunk-unique evaluations, and raw counts
include overlap screening work. RUNs 18–20 below record the historical one-second
merge rule; the episode correction and its new comparison are documented below.

## Sustained-encounter correction

### Root cause and investigation of all 22 extra TCAs

Each chunk keeps its own best coarse candidate for a pair. During sustained
proximity, adjacent chunks can choose different candidates and therefore different
`candidate_time +/- 60 s` refinement windows. A numerical minimum can lie at one
of those windows' endpoints, even while the pair remains inside 10 km throughout
the interval. For example, candidates at offsets 0 and 900 seconds can produce
TCAs near 0.006418 and 840.004600 seconds. These are separate local search results
for one threshold episode. The old one-second deduplication rule cannot connect
them. No change to SGP4, candidate generation or the minimizer is needed.

The initial 31-sample diagnostic found 20 pairs below threshold for the whole
30 minutes. Replaying **all 22 pairs** with their exact persisted elements at
0.1-second diagnostic intervals found **no exit between either pair of TCAs**.
The largest sampled intervening distance across all cases was 9.522819 km.
Those diagnostic samples alone are not the production continuity criterion;
the production enclosure described in the architecture document confirmed all
22 intervals using its stated conservative acceleration assumption.

The other two pairs leave the threshold only **after** their second reported TCA:

| Object IDs | TCA offsets from run start, s | Maximum sampled distance between TCAs, km | Distance at the 900 s boundary, km |
| --- | --- | ---: | ---: |
| 68425 / 68439 | 629.786476, 840.004600 | 9.205790 | 9.371581 |
| 70637 / 70638 | 433.153507, 840.004600 | 9.522819 | 9.787797 |

Thus these two cases also represent continuous encounters across the relevant
boundary, not exit/re-entry episodes. There are **zero remaining additional
events** in the corrected 30-minute comparison.

### Implementation and invariants

- Added a pure final-event episode merger and a streaming, adaptive continuity
  check. It checks full intervals between neighboring same-pair TCAs, split at
  the original global grid, and propagates only the final-event pairs concerned.
- The interval enclosure uses positions and the explicit Earth-orbit acceleration
  assumption documented in the architecture file. Original sample endpoints alone
  never establish continuity. An observed exit preserves separate episodes;
  unresolved continuity raises before database persistence.
- Every nonzero TCA gap requires continuity, including ordinary overlap solutions
  less than a second apart. There is no 15-minute, chunk-width or one-second
  suppression window. Equal TCAs already identify the same state.
- The representative is an existing refined result: smallest miss distance,
  then earliest TCA. The exact element IDs come from the run's original selection.
- No database/schema migration was added. The existing duplicate counter now
  includes events merged within an episode. `episode_checks` and
  `episode_propagation_attempts` are service/worker diagnostics only.
- Coarse candidate memory, chunk width, shared sample, global refinement bounds,
  10 km threshold, SGP4, cKDTree and the linear/curvature prefilter are unchanged.
  The merger retains only final events and a bounded subdivision stack.

An initial benchmark attempt rejected a sub-millisecond overlap because a draft
consistency assertion assumed SGP4 velocity was the exact derivative of the
propagated position series. For pair 188/39320, the 0.000683-second gap showed a
roughly 0.069 m/s difference between reported and finite-difference velocity.
That invalid assertion was removed; the position-based enclosure and checks for
observed bound violations remain. A regression test covers this case. The failed
attempt persisted no run or events; successful measurements below use the fix.

## Remaining limits and later benchmarks

- Candidate memory is bounded per chunk; selected elements, global timestamps
  and final events still consume memory proportional to their counts.
- The existing spatial query materializes one snapshot's raw candidate list
  before the retained-pair guard checks it.
- The inherited engine retains one best coarse candidate per pair per chunk.
  Episode merging classifies those final events; it does not enumerate all minima
  within a chunk or recompute a global minimum for a merged episode.
- Continuity uses an explicit conservative Earth-orbit acceleration assumption.
  It is not a formal enclosure for every possible SGP4 element set. Unsupported
  or unresolved continuity aborts before persistence; see the architecture
  document for the bound, numerical padding and resolution cutoff.
- `unique_candidates` and `suppressed_shared_pairs` are sums of chunk-local
  distinct counts; they are not globally distinct counts for chunked runs.
- No 1-hour or 6-hour benchmark was run during this task. The successful 15/30-minute
  checks are the measured evidence; longer horizons remain future validation.
- Deterministic SGP4 is authoritative. No covariance/Pc, AI orbital mechanics,
  GPU work, multiprocessing, GUI or dashboard features were added.
