# v0.3 Step 5H: chunked conjunction screening

[Implementation validation and benchmark report](v0.3-step5h-validation.md)

## Execution and memory

Long monolithic runs retain millions of candidate pairs. Screening now runs
sequential **900-second (15-minute) chunks**, bounding coarse candidate memory
by one chunk. The canonical Earth-orbit ephemerides are selected once; their
exact element IDs are carried through to event persistence.

The service builds the existing global sample grid once, including its final
partial step when necessary. It slices this grid without reconstructing times.
At a 60-second step, a one-hour run uses inclusive sample indices `0..15`,
`15..30`, `30..45`, `45..60`. Adjacent chunks share exactly one timestamp and
reuse its state list, including its propagation failures and ephemeris-quality
decisions. Each global sample is propagated and counted once, but overlapping
samples are spatially screened in both chunks. Only the final chunk may be
shorter than the configured width. A horizon at or below the chunk width uses
one chunk, with the existing screening and refinement semantics.

Each chunk streams SGP4 states into the existing `cKDTree` screen, keeps its
best coarse candidate per pair, applies the unchanged conservative lightweight
linear prefilter, and performs the existing numerical SGP4 refinement. Search
bounds remain `candidate_time +/- step_seconds`, clamped to the **global run
start/end**, so refinement can cross a chunk boundary. No chunk edge clips an
encounter's search window.

The chunk helper returns only counters and final events. Its candidate tuple,
pair dictionary and candidate state references are released before the next
chunk starts. One overlap snapshot is retained. No global coarse pair set or
candidate list is maintained. Global timestamps, the selected catalog, and
final events still grow with the run; this is bounded *candidate* memory, not
constant memory for arbitrarily many final events. `ConjunctionGridResult.screening`
is now a counters-only summary with empty `candidates` and `conjunctions` tuples;
authoritative events remain in `refined_conjunctions`.

## Encounter episodes

Only final events are accumulated across chunks. After screening, the merger:

1. Normalizes each object pair to ascending IDs.
2. Sorts each pair's final events by actual TCA and checks the interval between
   neighboring TCAs with the **same selected SGP4 elements** used for screening.
3. Connects events only when their separation stays within the final
   `candidate_distance_km` threshold throughout that interval. An observed exit
   preserves two episodes, even if the TCAs are less than one second apart.
   Equal TCAs identify the same state without additional propagation.
4. Keeps the smallest miss distance within a connected episode, then the earlier
   TCA, with stable secondary tie-breaks for otherwise equal results. The previous
   TCA used to extend an episode is independent of its best representative.
5. Returns retained events in TCA, miss distance, and object ID order.

There is no elapsed-time suppression window. Checking the full interval between
TCAs handles refinement on either side of a nominal chunk boundary and continuous
encounters spanning several chunks. It also detects a threshold exit and re-entry
between original grid samples. No episode table or additional migration is needed:
the database uniqueness constraint remains `(run_id, primary_object_id,
secondary_object_id, tca)`. The representative keeps its numerical result and exact
selected element IDs; persistence never reselects canonical elements.

### Continuity enclosure and its limits

Checking only the shared boundary or all original grid samples cannot exclude an
exit between samples. `orbital_engine/conjunction/episodes.py` instead streams the
intervals between original global sample timestamps and adaptively subdivides
them, using authoritative SGP4 positions at additional timestamps when necessary.
For relative position with second derivative bounded by `A`, the deviation from
its endpoint chord is at most `A * dt² / 8`. Therefore an interval is inside when
`max(endpoint distances) + A * dt² / 8 + outward padding <= candidate_distance_km`.
Padding is 1e-9 km and makes acceptance stricter; the final threshold is unchanged.

The service uses `A = 8 * 2 * mu / Earth_radius²` (about 0.156773 km/s²), reusing the
existing curvature safety factor at the WGS72 Earth surface. **This is an explicit
conservative Earth-orbit acceleration assumption**, not a formal interval bound
proved for every pathological SGP4 element set. Sampled states below Earth's
surface, propagation failures, non-finite values, observed velocity changes or
position-chord errors inconsistent with this bound abort classification. The
observed checks can reject the assumption; they cannot prove it globally.

SGP4 reported velocities are not used as exact derivatives of the position series.
That identity is unsuitable for sub-millisecond overlap comparisons. The enclosure
itself depends on positions. If subdivision cannot resolve a grazing threshold at
0.01 seconds, the service raises `EncounterContinuityError` before persistence.
This resolution is a failure cutoff, never a reason to merge or split events.

Only repeated **final-event pairs** require continuity work. Depth-first
subdivision retains `O(log(step / resolution))` live states, with no trajectory
cache or retained coarse candidates. Episode aggregation uses `O(final events)`
memory; a single-chunk run has one final event per pair and performs no extra
continuity propagation.

The inherited screen still selects one best coarse candidate **per pair per
chunk**. It does not enumerate every possible minimum inside a chunk. Chunking
can therefore find additional encounters that a monolithic one-best-pair run
would omit. Episode merging only classifies the final events that this unchanged
screen/refinement pipeline produces; it does not search for missed minima inside
a chunk or recompute a global minimum for a merged episode.

## Metrics

| Field | Meaning |
| --- | --- |
| `samples` | Number of distinct timestamps on the global grid. |
| `propagation_attempts`, `propagation_failures`, `expired_skips` | Grid work per global sample; reused boundaries do not add counts. Refinement and episode propagations remain separate from these historical grid counters. |
| `raw_candidates` | Sum of raw spatial detections across chunks, including overlap detections and subsequently excluded shared-solution pairs. |
| `unique_candidates` | Sum of **chunk-unique candidate evaluations**; a pair may contribute once in each chunk. Not a globally unique pair count. |
| `suppressed_shared_pairs` | Sum of distinct suppressed shared-solution pairs within each chunk. |
| `shared_solution_groups`, `shared_solution_objects` | Catalog-level counts, computed once for the run. |
| `refinement_attempts`, `refinement_failures` | Sum of numerical refinement work across chunks. |
| `chunk_count`, `chunk_seconds` | Actual number of chunks and configured logical width, including for a short final chunk. |
| `duplicate_events_suppressed` | Final events removed within a continuous threshold episode, including ordinary overlap duplicates. |
| `episode_checks`, `episode_propagation_attempts` | Continuity intervals checked and individual SGP4 calls for their two objects. Returned by the service and printed by the worker; not persisted or added to the API schema. |
| `max_chunk_raw_candidates`, `max_chunk_unique_candidates`, `max_chunk_refinement_attempts` | Largest corresponding workload observed in any one chunk. |
| `event_count` | Retained events after deduplication. |
| `duration_ms` | Screening service time, including event merging; excludes database persistence, as before. |

All six new chunk metrics are persisted and exposed by the existing latest-run
API schema. Migration `d28f6b91c4a7` follows `a84f17c92b61`. Historical runs are
backfilled as one chunk spanning their full window (rounded up to a full step),
with maxima taken from their original counters and zero duplicates. Columns have
non-null defaults. Downgrade refuses to restore pair-only uniqueness if stored
runs already contain multiple encounters per pair; it never deletes events to
force a downgrade.

## Configuration and guardrails

| Environment variable | Default | Rationale |
| --- | ---: | --- |
| `ORBITAL_SCREENING_CHUNK_SECONDS` | `900` | Validated 15-minute candidate working set. Must be positive, at least the step, and an exact multiple of the step. |
| `ORBITAL_SCREENING_MAX_OBJECTS` | `40000` | Retains the existing full-catalog coverage guard. |
| `ORBITAL_SCREENING_MAX_PROPAGATIONS` | `12000000` | Total estimated **grid** work: selected objects times global samples. About 30k objects at 60-second steps over six hours need 10.83M attempts. Chunking does not remove the total-work limit. |
| `ORBITAL_SCREENING_MAX_CHUNK_UNIQUE_CANDIDATES` | `4000000` | Headroom above RUN 17's 2.62M unique candidates per 15 minutes. Checked before inserting a new candidate beyond the cap. |

The candidate guard raises `RuntimeError` with the chunk number, global sample
indices, timestamp bounds and configured limit. It aborts the run before event
persistence. The cap bounds the retained best-pair dictionary; the existing
`cKDTree` query and its candidate list for one snapshot are still materialized.
An unusually dense single snapshot can therefore use additional transient
memory before this guard is checked.

`run_conjunction_grid()` and `execute_conjunction_screening()` accept
`chunk_seconds: int | None = None`; `None` reads the setting. The worker supports
`--chunk-seconds`, `--start-time` (timezone-aware ISO 8601), and `--summary-only`.
All run metrics remain visible in summary mode.

Existing `.env` values override Compose defaults. If an installation explicitly
sets the old 2.5M propagation budget, it must opt into 12M to run longer horizons.
Changing the default does not override local configuration or credentials.

## Validation and local commands

From `/home/lele/projects/orbital-ai`, build and apply the migration before using
the new worker/model:

```bash
docker compose --env-file .env -f deploy/compose/compose.core.yml build api
docker compose --env-file .env -f deploy/compose/compose.core.yml run --rm --no-deps api python -m alembic upgrade head
```

One-hour benchmark (explicitly opts into the intended total-work budget):

```bash
cd /home/lele/projects/orbital-ai
docker compose --env-file .env -f deploy/compose/compose.core.yml \
  run --rm --no-deps \
  -e ORBITAL_SCREENING_MAX_PROPAGATIONS=12000000 \
  api python -u -m workers.conjunction.run_screening \
  --hours 1 --step-seconds 60 --chunk-seconds 900 --summary-only
```

Later six-hour benchmark, after checking shorter-run results and resources:

```bash
cd /home/lele/projects/orbital-ai
docker compose --env-file .env -f deploy/compose/compose.core.yml \
  run --rm --no-deps \
  -e ORBITAL_SCREENING_MAX_PROPAGATIONS=12000000 \
  api python -u -m workers.conjunction.run_screening \
  --hours 6 --step-seconds 60 --chunk-seconds 900 --summary-only
```

For reproducible comparisons, supply the same `--start-time` and keep the catalog
unchanged. Compare normalized pair plus TCA within one second, then inspect miss
distance differences. A 30-minute single-chunk reference uses `--chunk-seconds
1800`; its memory demand is higher and it may require an explicit temporary
candidate-cap override. Keep the normal 4M guard for operational chunked runs.
The one-second tolerance here is for comparing numerical results across benchmark
runs; it is no longer the production event-merging rule. The six-hour command is
complete and opts into 12M grid propagations; a six-hour run has not been validated.

Automated tests exercise global slices and partial final steps, cross-boundary
numerical searches, overlap reuse including expiry/failure, release of candidate
objects between chunks, distinct same-pair encounters, guardrails, event identity,
SQL uniqueness, persistence rollback, API metrics and exact element provenance.

## Scientific scope

Deterministic SGP4 remains authoritative, with C++ acceleration where available.
The existing cKDTree screening, conservative linear prefilter and SciPy numerical
minimization retain their physics and thresholds. There is no covariance or
probability-of-collision (Pc) implementation. AI performs no orbital mechanics.
